## 2. 项目范围与交付状态

项目采用 Django 模板与 JavaScript 实现 Web 聊天，Django/Channels 提供 HTTP 与 WebSocket 服务，Electron 提供 Windows 桌面壳。主要功能包括账号、联系人、私聊、群聊、加密文件、消息管理、设置及独立 AI Assistant。

截至已有的 2026-10-07 审计，Phase4 原始任务为 29/78 闭环、49 项开放；这不是 2026-10-12 的在线统计。继续开发前应核对对应 GitHub Issue 与最新证据。

| 范围 | 已有资料记录的状态 | 接手注意事项 |
| --- | --- | --- |
| 云部署 | PostgreSQL/Redis、HTTPS/WSS、健康接口及备份恢复路径已有验收 | 监控告警、完整发布门禁仍待做 |
| 消息可靠性 | 统一事务写入、幂等、ACK、退避重连及游标补取已实现 | 事件仅覆盖部署后的新增消息；撤回/删除同步与历史回填待做 |
| Windows | 云模式、安装/卸载、品牌、托盘、连接恢复与敏感存储已有验收 | 通知最终布局复验 #145、文件桌面集成 #146 仍开放 |
| Android | 未有已交付工程/APK | 先完成技术选型和兼容验证，不能直接声明支持 |
| 多设备与发布 | 设备级身份/撤销/分发、自动更新尚未完整交付 | 按任务依赖继续设计和验收 |

待发箱位于内存，断网与托盘隐藏可保留；页面刷新、客户端重启或崩溃不保证恢复未确认消息。长期私钥为 IndexedDB 中不可导出的 CryptoKey，桌面草稿等使用 safeStorage；Web 草稿/AI 历史及旧记录迁移仍有存储限制，详见协议。

## 3. 代码入口与维护边界

| 目录或文件 | 职责 | 修改时需要同步 |
| --- | --- | --- |
| `accounts/` | 用户、账号设置、公钥与信任关系 | 权限测试、账号 API、模型迁移 |
| `chat/models.py` | 会话、消息、附件及事件模型 | 数据库说明、迁移与可见性规则 |
| `chat/views.py`、`chat/consumers.py` | HTTP/WS 入口 | 鉴权、错误码与协议测试 |
| `chat/services/messaging.py` | HTTP/WS 共用事务写入、幂等与副作用 | 消息服务和并发测试 |
| `chat/services/sync.py` | 事件补取、游标及按用户可见性投影 | sync API 与权限测试 |
| `static/js/chat-connection.js` | 连接状态、重试、ACK 与待发箱 | JavaScript 回归与平台联调 |
| `static/js/key-manager.js`、两套 `*-chat-e2ee.js` | 密钥管理及私聊/群聊加解密 | 加密向量、公钥信任和历史兼容 |
| `templates/`、`static/` | 页面、交互及样式 | 明暗主题、窗口尺寸与桌面布局检查 |
| `desktop/` | Electron 主进程、preload、IPC、安装与原生集成 | IPC 信任边界、Windows 专项检查 |
| `ichat_pro/` | 配置、ASGI、中间件与健康检查 | 环境模板、部署与配置测试 |
| `deploy/`、`.github/workflows/django.yml` | 运维脚本与持续集成 | Runbook、实际命令与验收证据 |

不要在 View、Consumer 中另建消息写入路径绕过服务层。`created` 分支才执行新增消息副作用；重放不应重复计未读或广播。更改公钥、密文格式、同步游标或 IPC 时，先确定兼容契约并找相关模块维护人评审。

## 4. 从零启动开发环境

以下命令使用 Windows PowerShell，从新克隆的仓库开始。已有仓库无需再次 clone。

```powershell
git clone https://github.com/HeanX/iChat_Pro.git
cd iChat_Pro
python --version
node --version
npm --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
npm ci
$env:DJANGO_DEBUG = 'True'
$env:DJANGO_ALLOWED_HOSTS = 'localhost,127.0.0.1'
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

使用 Python 3.13+；当前 CI 使用 Python 3.13、Node.js 24。Python 依赖以 `requirements.txt` 为准，根目录和 desktop 的 Node 依赖分别以各自 lockfile 为准。若激活脚本受本机策略限制，可用 `.\.venv\Scripts\python.exe` 替代命令中的 `python`。

浏览器访问 `http://127.0.0.1:8000/`。未设置 `DATABASE_URL` / `REDIS_URL` 时默认 SQLite 与内存通道；确认终端未继承生产连接配置后再执行迁移或演示脚本。需要演示数据时，仅在隔离的本地数据库运行 `python demo_setup.py`；alice、bob、carol 的演示密码为 `demo1234`。

`settings.py` **不会自动加载 `.env`**，复制 `.env.example` 不会使其生效。开发可用进程环境变量；生产配置由部署流程加载，参考 [生产环境模板](../deploy/env.production.example)。

| 配置 | 用途 |
| --- | --- |
| `DJANGO_DEBUG` | 默认 True；生产必须 False |
| `DJANGO_SECRET_KEY` | 生产必填，通过安全渠道移交 |
| `DJANGO_ALLOWED_HOSTS` | 允许访问的主机名，逗号分隔 |
| `DATABASE_URL` | PostgreSQL 等数据库连接；不设置则使用本地 SQLite |
| `REDIS_URL` | Redis 通道与缓存；不设置则使用进程内实现 |
| `DJANGO_STATIC_ROOT`、`DJANGO_MEDIA_ROOT` | 生产静态产物与持久媒体目录 |
| `ICHAT_SERVER_URL` | 桌面服务 Origin，显式设置优先于 dev 模式 |
| `ICHAT_HOST`、`ICHAT_PORT`、`ICHAT_PYTHON` | 桌面本地开发时的 Django 启动配置 |

修改 Tailwind 输入后运行 `npm run build:css`；开发监听可用 `npm run watch:css`。数据库并发与跨进程广播的正式验证需要真实 PostgreSQL/Redis，参考 CI 的 integration job。

### Windows 客户端

```powershell
cd desktop
npm ci
npm run dev
```

开发模式通常启动本地 Django，使用根目录 `.venv` 中的 Python；如终端已设置 `ICHAT_SERVER_URL`，客户端会优先连接该地址。不要同时让另一个服务占用开发端口。

`npm start` 默认加载 `desktop/defaults.json` 中的云服务，不启动本地 Python。远程地址要求 HTTPS，loopback HTTP 可用于开发。`npm run dist` 构建 Windows 安装包，产物位于 `desktop/dist/`；构建成功不能代替真实安装/卸载验收。

## 5. 验证和交付证据

根目录执行：

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
npm run test:e2ee
```

涉及桌面时在 `desktop/` 执行 `npm run test:layout`、`npm run test:branding`、`npm run test:installer`。installer 检查需要 NSIS 编译器，可通过 `MAKENSIS` 指定。涉及数据库事务、幂等和广播时，确认 PostgreSQL 16 / Redis 7 的 integration job 通过。

2026-10-07 的 [CI 记录](https://github.com/HeanX/iChat_Pro/actions/runs/37630595919) 显示四项 job 通过，SQLite 和 PostgreSQL/Redis 各 404 条 Django 测试；此处保留历史证据，不代表本次重新跑过这些测试。每次交接填写实际命令、环境、SHA、结果及未执行范围。

建议最小业务冒烟：两个隔离浏览器会话登录不同本地账号，验证私聊收发与解密、群聊收发、加密文件上传下载、断网恢复补取及无权限操作被拒绝。桌面相关改动另外验证真实客户端窗口、通知、托盘与安装路径。

## 6. 生产、数据与权限移交

已有记录的生产基线为 `f2f60ec`，Web 入口为 `https://chat.20060810.xyz:8443`；本地文档提交 HEAD 与生产 SHA 不同。安装包 SHA-256 独立记录，不能用 main SHA 代替。

运维接手需按 [Runbook](../deploy/runbook.md) 核对服务账号、环境配置、Nginx/TLS、PostgreSQL/Redis、备份和恢复权限。发布入口为 `/opt/ichat/bin/deploy.sh`，实际部署记录在 `/opt/ichat/DEPLOYMENTS.log`。回滚应用不会自动降级数据库，先评估迁移兼容性与备份。

源码交付不包含 `.env`、数据库、用户媒体、私钥、Token、本地依赖或 dist 二进制。按需通过安全渠道单独移交备份和凭据；用户端密钥备份不能由服务器数据库推导。服务器共存服务端口与操作限制以 Runbook 为准。

4. 补齐监控告警、覆盖率/扫描门禁、受保护分支与完整发布审批。
5. 按需求矩阵推进多设备、撤回/删除事件同步和历史迁移等后续范围。

| 现象 | 优先检查 |
| --- | --- |
| 修改 `.env` 后配置没有变化 | 环境是否真正注入进程；重启后确认，避免打印秘密 |
| 页面可用但消息不实时更新 | ASGI/WS 路由、会话认证、Origin 与 Redis 配置 |
| 本地与 CI 数据库结果不同 | SQLite 与 PostgreSQL 的事务、锁和真实迁移差异 |
| 桌面连接到错误服务 | `ICHAT_SERVER_URL` 优先级、defaults、dev 模式与端口 |
| 旧消息无法解密 | 原浏览器/用户目录、密钥备份与历史公钥；不要直接清空存储或换钥 |
| 健康接口成功但用户功能失败 | 登录、权限、解密和真实业务冒烟；健康探针只证明其检查范围 |
