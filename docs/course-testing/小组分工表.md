## 2. 分工原则

1. 每个 GitHub Issue 指定一名主负责人和至少一名验收人。
2. 开发人员不得单独验收自己的关键功能；测试负责人保持相对独立。
3. 每名成员都应承担可量化的开发、测试或工程任务，并提交可追溯证据。
4. 安全、E2EE、生产部署和发布操作至少由两人复核。
5. 任务调整以 GitHub Issue 的 Assignee、评论和本表更新记录为准。

## 6. 工作与汇报机制

- 领取任务：成员在 GitHub Issue 中设置 Assignee，并评论预计完成时间和依赖。
- 日常更新：至少在开始、提交 PR、测试完成和遇到阻塞时更新 Issue。
- 代码评审：由非作者成员评审；涉及相邻模块时邀请对应负责人参与。
- 测试验收：测试负责人依据验收标准给出通过、失败或阻塞结论。
- 周期检查：每周至少一次核对 Issue、PR、缺陷、测试证据和风险。
- 变更管理：范围、负责人或截止时间改变时，在 Issue 和本表中同步记录。
