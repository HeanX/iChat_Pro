# Phase4 需求与验收基线

> 版本：交接草案 v1.0 / 2026-10-01  
> 范围：本学期跨平台安全即时通信与软件测试实践。  
> 本文将已有需求整理为可执行口径，不宣布任何新增功能已完成。

## 1. 产品目标

把现有 Django Web 聊天系统交付为可安装的 Windows App 和 Android App。两端连接同一公网服务，在真实网络和独立设备上完成双向 E2EE 聊天，能解释和恢复断线、重复提交、遗漏消息与平台生命周期异常，并提交可复核的测试证据。

继承基线包括账号、资料、联系人、私聊、群聊、文件加密传输、消息管理、设置和独立 AI Assistant。继承能力应回归验证，不重复计为 Phase4 新增成果。

## 2. 优先级与最小交付

| 等级 | 交付内容 | 判定规则 |
| --- | --- | --- |
| P0 必须 | Windows 安装包、Android APK、公网 HTTPS/WSS、ASGI、PostgreSQL、Redis、持久化存储、双向文本聊天、重连、幂等、补取、安全存储、E2EE 边界、核心测试/CI、备份恢复和报告 | 正常、异常、安全路径均有真实证据；任何失败不得标记核心交付完成 |
| P1 应当 | 托盘/系统通知/文件集成、完整兼容性与生命周期验证、跨端群聊文件验证、多设备新消息分发与撤销、UI 自动化、性能稳定性、监控、测试部署与发布回滚 | 明确列出已通过、缺陷和未完成项，不能用占位代替 |
| P2 增强 | 完全退出后的云推送、自动更新、经授权历史密钥迁移、对象存储/灰度扩展 | 不阻塞 P0；先有设计和验证计划再实施 |

不纳入核心范围：语音/视频、iOS、完整 Signal/Double Ratchet/Sender Key、Channel/Bot/RAG/Agent Gateway、商业审核与计费。保留已有 AI Assistant 的独立边界。

### 3.5 E2EE 与设备

| 需求编号 | 要求 | 优先级/任务 | 核心验收 |
| --- | --- | --- | --- |
| NEW-DEV-006、008 | 新设备历史限制、平台安全存储 | P0 / P4 T21、T29、T38–T39 | 新设备无私钥不得自动解密旧历史；丢钥有明确恢复/重新建钥提示 |
| NEW-DEV-001–005、007 | 设备标识、独立密钥、设备列表/撤销、逐设备分发、变化提示 | P1 / P4 T40–T42 | 两台设备使用不同私钥，各自可解密新消息；撤销设备不再取得后续密文/密钥材料 |
| NEW-DEV-009 | 历史迁移 | P2 / P4 T43 | 用户授权、端侧加密、失败恢复和撤销边界均有说明与验证 |

共同安全约束：

1. 服务端仅持有密文、公钥和必要元数据；不存聊天/文件明文、用户私钥、消息会话密钥或明文文件密钥。
2. 私聊历史和推送仅返回当前查看者的密文副本；群聊仅返回当前用户/设备对应的副本。
3. 新成员不能取得加入前未分发给自己的密文；移除成员和撤销设备不能取得后续密钥材料。
4. 新公钥/设备不自动继承旧指纹的已验证状态。
5. AI Assistant 仅接收用户主动输入内容，不自动读取 E2EE 内容或密钥。
6. `sender_copy`、临时 ECDH 公钥和用户级公钥版本，不等于已实现独立设备密钥或完整前向保密。

## 5. 最终综合验收脚本

1. 在无开发依赖的 Windows 环境安装正式包；Android 真机/独立模拟器安装 APK。
2. 两个账号从不同设备访问同一公网服务，完成账号和联系人操作。
3. 两端互发文本，核对内容、发送者、服务端时间、状态及双方历史。
4. Android 断网，Windows 发送多条消息；恢复网络，30 秒内重连并补取。
5. 故意丢弃 accepted 响应，再通过 HTTP 与 WS 重试；数据库只有一条，UI没有重复，未读不重复增长。
6. 重启客户端与应用服务，检查消息、联系人和待发送项；验证私钥未被静默替换。
7. 群聊加入/退出/移除及跨端密文文件测试，记录 P1 实际完成情况。
8. 检查 DB/API/日志/安装包/平台存储，使用测试哨兵验证无明文、私钥泄漏。
9. 进行 PostgreSQL/文件备份与独立恢复，核对数量、关系和抽样文件。
10. 展示 CI、覆盖率、专项报告、真实缺陷闭环与明确的未完成项。

## 6. 每项任务的完成定义

任务必须有：范围与需求编号、实际代码/配置、必要迁移、非作者评审、可复现验证、证据、已知限制，以及对应文档更新。不能把“代码存在”“测试已编写”“本地能打开页面”当成跨端安装与公网验收通过。
