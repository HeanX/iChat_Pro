### 2.2 文档维护纪律

文档体系有三条硬约束，用于避免"文档写了就算完成"：

1. **状态来源有优先级**：实际代码/部署 > 具体 CI 记录 > 原生或专项验收 > 对应 Issue。需求文档和规划文档**不构成完成证据**。
2. **三种 SHA 分开记录**：`main` 提交、生产部署版本、安装包 SHA 是三个独立版本证据，不得互相替代。
3. **历史结果不改写**：旧实验报告和验收报告保留原日期与原结论，新结论以追加带日期说明的方式补充，不覆盖当时的测试结果。

仓库在 Issue 与 PR 模板中内建了文档同步要求。PR 模板强制勾选：

- 接口、模型、协议、存储或平台行为已同步到相应现行文档，历史结果没有被覆盖；

- 原生、跨端、迁移和发布验收范围及未完成项已如实注明，**CI 全绿不代替这些证据**。

### 4.2 已交付的核心代码能力

**统一消息写入路径。** `chat/services/messaging.py` 是 HTTP 与 WebSocket 共用的唯一事务写入实现。事务顺序为：结构校验 → 会话行锁 → 身份/权限校验 → 幂等重放判定 → 新消息检查 → 插入 → 计数与事件。设计目标是两条入口不可能产生行为漂移——这是评审 R-03/R-04 风险后的整改结果。

**幂等与并发。** `(sender, client_message_id)` 重放时，从持久化列**重新计算内容摘要**并比对，内容不同返回 409 而非错误重放。并发同 ID 插入依赖数据库唯一约束触发 `IntegrityError`，用嵌套 `atomic`（savepoint）只回滚 INSERT 而不破坏外层事务，然后恢复查询。合法重放不重复计未读、不重复广播、不重复生成事件。

**增量补取。** `Conversation.sync_sequence` 与 `ConversationEvent` 在会话行锁内分配序号，保证并发发送不会撞号。游标用 HMAC-SHA256 签名并绑定用户与会话，TTL 7 天。补取的可见性投影与历史接口同源，包含清空、个人删除、自动删除、拉黑和群 pre-join 边界。

**端到端加密边界。** 长期私钥是 IndexedDB 中**不可导出**的 CryptoKey，服务端只中转和保存密文。桌面端待导出备份、聊天草稿与 AI 历史通过 safeStorage 加密；桥不可用时不新增明文写入。私聊保存接收者密文与发送者独立副本，群聊为每个有效成员保存独立密文。

**协议与错误契约。** `chat/errors.py` 是错误码单一注册表（25 个已注册码），每个码定义 HTTP 状态、是否可重试和默认文案。客户端按**码**分支而不是按文案匹配。API 未登录返回 401 JSON 而非 HTML 重定向，WebSocket 用 4401/4003 关闭码。

**桌面客户端。** 默认连接云服务（`https://chat.20060810.xyz:8443`），不启动本地 Python；开发模式显式启用。单实例锁先于网络与启动服务，托盘隐藏/恢复同一窗口不重载页面，退出时清理进程与托盘。品牌 AUMID 与 `build.appId` 对齐。

**运维与健康检查。** `/health/live/` 与 `/health/ready/` 公开响应只返回状态词，失败细节写日志而不泄露内部拓扑；readiness 实际探测数据库与缓存往返。部署统一使用仓库外稳定脚本，支持指定 SHA 回滚，回滚应用不会自动降级数据库。

### 5.1 已识别但未修复的问题（风险登记 R-01–R-07）

项目在初期做过一次静态代码取证，确认 7 项风险并全部进入整改，当前均已闭环：

| 编号 | 问题 | 处置 |
| --- | --- | --- |
| R-01 | 私聊幂等命中先于会话/权限校验 | 权限先于幂等，跨会话 ID 返回 409 |
| R-02 | 群聊幂等查询在成员版本校验之后 | 合法重放先于当前成员版本处理 |
| R-03 | HTTP 与 WS 私聊序列化路径漂移 | 两条路径共用服务与 viewer 投影 |
| R-04 | 幂等重放仍重复广播、无 created 区分 | created/replayed 区分，重放零副作用 |
| R-05 | 在线状态依赖非标准接口、异常被吞 | 改用缓存连接计数 |
| R-06 | API 认证失效返回 HTML 重定向 | 改为 401 JSON / WS 4401 |
| R-07 | 生产配置缺口（代理信任/CSRF/静态收集/URL 静默回退） | 非法 DATABASE_URL 启动失败，补代理与静态配置 |

### 5.2 尚未验证的边界

- 待发箱仅在内存，页面重载或进程重启**不保证**未确认消息恢复；
- 补取只覆盖部署后的新增消息，**未回填历史**，也**未同步**撤回/删除变更事件；
- 离线加密需要已缓存公钥，首次无缓存时不能离线建立新的加密收件关系；
- 未配置商业代码签名证书。

## 八、结论

中期项目已经具备**可安装、可公网访问、可真实跨设备加密通信**的可用形态：云端服务与数据库已上线，Windows 客户端已完成安装/卸载/托盘/通知/连接恢复/敏感存储的验收，后端消息链路（统一写入、幂等、补取、排序）已闭环，文档体系完整且维护规则明确。

同时，项目**尚未达到全部 P0 交付**：Android 完全未开始，多设备与设备级安全未实现，测试工程质量门禁不完整，部分原生验收（通知布局、文件集成）仍在等待真实环境复验。

本轮新增的实际产出包括：修复了长期污染工作区的测试缺陷（累计 82 个可证明的测试产物）并清理；统一了文档索引的日期与基线口径；补齐了单元测试与代码评审的过程记录。代码与全部文档已提交。
