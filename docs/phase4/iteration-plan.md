## 4. 降级方案（做不完 / 做不成时）

按风险从高到低，每张卡预先写明降级后的最小可接受产物。原则：**降级降的是范围，不是证据标准**——降级产物仍须真实跑过并如实标注"未验证范围"。

| 风险 | 触发条件 | 降级方案 |
| --- | --- | --- |
| 本机/服务器资源不足，无法搭 staging 实机（t3.small 1.9GiB） | W1 末 staging 未搭建 | 降级接受：`check_isolation.sh` 全绿 + systemd 单元/脚本评审通过，Issue 注明"隔离代码就绪、实机待建"；staging 实机顺延到 W3，不阻塞 R2 |
| Android 环境缺失（JDK/SDK/真机） | W3 末无法构建 APK | #149 ADR + #151 工程骨架 + 配置契约测试照常交付；真机验收项显式标"未验证"；#185/#197 顺延，不假装通过 |
| 多设备密钥分发改造风险高（#169 会改 recipients 语义） | 设计评审发现影响面超预期 | 只交付 ADR + 兼容性影响分析，不改服务端协议；#170（P2）直接放弃本轮 |
| 真机验证通道不可用（无 SSH / 服务器变更） | W2 仍无生产证据 | 全部部署类卡保持"未在生产验证"状态进入最终材料；#181 的材料里明确列出未验证矩阵，不做"代码已实现=验收通过"的替换 |
| 时间不足，R4 跨端集成做不完 | W5 末仍有 ≥2 张 R4 卡未完成 | 保 #194（HTTP/WS 集成）与 #203（测试总结）这两个不依赖 Android 的卡；#199/#200/#201 记录为"未执行"而非降级通过 |
| 并行会话冲突（git 分支/worktree 争用） | 任何时刻 | 一律在独立 worktree 分支开发（本批已如此执行）；共享文件（tasks.md/runbook）合并前 rebase；冲突时以先合入者为准，后合者重放 |
